# MF paper: harvest of HPG results, Oct 19 (MF_SUMMARY)

Primary serial baseline everywhere: Richard's NEW serial MF1 (rmain 598b013, job 46754897, milan, 1 core). Every graph has a new-serial-MF1 row; none missing (47/47, same for new AMF). Old MF1 (mt) is secondary.

## Verdicts

1. MF1 beats AMD sequentially: YES on fill, 11 of 14 graphs (nnz median 0.863x AMD, flops median 0.729x; flops win 11/14). Losses: lat2_100 (1.02/1.06), lat2_224 (1.05/1.14), lat2_724 (1.145/1.49), all 2D lattices. METIS-ND nnz median 0.79x AMD (it wins on lattices/big meshes); AMF new median 0.89x. Only 14 graphs (<=1M) have an AMD row: Richard's new AMD failed on all 47 (`import AMD` missing in env; see Flags), so AMD is from the old env (base_milan).
2. GPU MF1 matches serial MF1 quality: partly. nnz(L) GPU/new-serial MF1 (crit2 file):
   - v2 single: median 1.021, max 1.754 (lat3_140; lattices 3D 1.4-1.75), 41 graphs.
   - u0.1 single (urelax=0 fix): median 1.014, max 1.253 (Queen_4147), lat3_100/140 1.21-1.22, lat3_40 1.18.
   - ensemble (best k available per graph, 38 graphs): median 1.001, max 1.212 (lat3_140, k=4). ens8 only (17 graphs): median 0.9996, max 1.095 (lat3_40); 8 members reach the target (max <=1.10) but only on graphs up to 187k.
   - Medians are near 1; max misses the 1.05 bar on 3D lattices and Queen (ens max 1.21). Flops median 1.000 (ens), max 1.29. Width median 0.98.
   - GPU is below serial MF1 by up to 14-25% on 3D FEM (Geo_1438 0.86, StocF 0.89, Bump 0.75, u0.1) which is a quality gain, not a flaw, but it is much slower (below).
3. Speed vs new serial MF1 (median serial/GPU; fast = rr/v2 fill-config, ens/u0.1 = quality configs; B200 vs milan core):
   - n<30k: fast 0.60x, u0.1 0.24x, ens 0.12x. 30-100k: 0.93x / 0.57x / 0.29x. 100k-1M: 3.3x / 2.5x / 0.82x. 1-3M: 4.6x / 2.8x / 1.75x. >=3M (4 graphs): 16.7x / 14.8x / 4.7x (ens only 2 graphs).
   - Crossover vs new MF1: fast config wins from ~95k and on every graph above that (first win at 3k, small-graph noise); u0.1 wins on most graphs above ~45k but loses on 3D FEM >1M (Geo 0.48x, StocF 0.37x, Flan 0.72x, Bump 0.52x, Queen 0.25x), sustained only from n=8.2M; ensemble sustained from ~1.6M, first win 523k.
   - vs AMF new (much faster serial): fast config sustained from ~3M (first win 147k, loses G2_circuit 0.32x, ecology2 0.89x, Bump 0.56x); u0.1 only >=8M; ens only from ~3M. vs AMD (old env, 14 graphs): wins only parabolic_fem (n=526k) and lat2_724+; AMD is 2-8x faster than GPU below 500k.
   - Ensemble time cost: median 2.6x the single u0.1 run (k=2: 1.4x, k=4: 3.0x, k=8: 2.6x), 3.3x the fast config, so the 8 CUDA-stream overlap does not hide work; per size 1.6x (<30k) to 3.2x (>3M).

## Flags
- Richard's new serial AMD: 47/47 rows failed ("`import AMD` to use algorithm AMD", rmf_milan.tsv, 46754897). Rerun needs `using AMD` in rport/sbench.jl. AMD/METIS-ND only for 14 graphs from base_milan (old env, 46747636).
- Fast (rr/v2) config fill differs from u0.1: v2 is up to 1.75x serial nnz on 3D lattices; speed claims at "fast" are NOT at serial-equal fill. At equal quality use u0.1/ens times.
- rr (Richard grouped-mask port) fill identical to v2 on all 47 graphs and dg32 identical; rr speed vs v2 median 1.01x but 4-9x on dense graphs (rndhyp, mc3sat, qaoaamp, Bump 7x). No fill mismatch between jobs 46736366, 46754896, 46747676 (v2) and 46702561 (GPU-MF1 nnz identical on 20/20; 46702561 times are 1.4-3x slower than the later v2 job).
- Ensemble coverage incomplete: ens8 on 17/41 graphs, ens4 32, ens2 38; none for Queen_4147, Bump_2911, StocF-1465 (and qaoaamp only ens2). The ensemble job output ends there (job no longer in squeue). Graphs rndhyp/mc3sat/lat3_16/lat2_362/lat2_1448 have no u0.1/ens rows (rr/v2 only).
- u0.1 on Bump_2911 takes 451 s (vs 71 s v2, 237 s serial MF1 new); Geo 14 s, StocF 47 s, Queen 43 s: more rounds on 3D FEM. This is why quality-config speedups collapse there.
- GPU nnz below serial by 14-25% on Geo/StocF/Bump: counts are device counters (checked against CliqueTrees on a subset per ENSEMBLE_NOTES); not re-verified here on large graphs. Worth a CliqueTrees recount of Bump_2911 u0.1.
- 46702562 (CPU baselines for large set) still pending; 46702563 outputs not found separately (fill/results holds only GPU-MF/MF1/MD rows, fill consistent with rr job). GPU-MF and GPU-MD fill are 1.06-1.24x and 1.1-2.8x MF1 fill.
- Serial MF1 relabeling spread (base_milan MF1-rl*) applies to reference noise (ENSEMBLE_NOTES: median 1.00, max 1.05).
- Platforms differ: GPU rows B200 (various nodes), serial rows milan single core; AMD/METIS rows older env (mt) same host class.
