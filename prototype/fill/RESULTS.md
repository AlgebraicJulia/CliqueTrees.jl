# Fill quality: exact minimum fill (serial and GPU-round) vs AMD

Laptop only (Legion 5, RTX 5060 shared, `taskset -c 1-8`, Julia `-t1`). Unit weights (graph = sparse symmetric pattern, diagonal dropped). 27 graphs: 16 SuiteSparse SPD (10k-1M rows: 2D/3D PDE, structural, thermal) and the 11 TN/lattice graphs of `rounds/results/paramd_laptop.tsv`.
Metrics from CliqueTrees column counts (`evalutil.jl colweights`, unit weights, so cc includes the diagonal): nnz(L) = sum cc; flops = sum cc^2; tw = max cc - 1. Every ordering asserted a valid permutation. Time = min of 2 runs (1 run when n > 150k), warm (compile excluded); CliqueTrees orderings take a prebuilt BipartiteGraph; GPU-round times take a SimpleGraph and include graph upload.
nnz(L) of AMD equals the SSMC `amd_lnz` column (checked on jnlbrng1), so AMD here is the SuiteSparse AMD (AMD.jl, defaults dense=10, aggressive=1).

Orderings: AMD = SuiteSparse AMD via CliqueTrees `AMD()`; AMF = CliqueTrees approximate minimum fill; MMD; METIS-ND = CliqueTrees `METIS()` (Metis.jl nested dissection, default options); MF = exact minimum fill, `MF()` (strategy 0); MF1 = `MF(strategy=1)` (min average fill); GPU-MF / GPU-MD = `GRounds.grounds` with `RoundsAlg(score=:mf|:md, relax=0.1)`; ParAMD-t1/t8 = `dl_paramd/ParAMD/build/paramd` (mult 1.1, lim 8192), 1 and 8 OpenMP threads.
Caveats: GPU-MF ran out of GPU memory on ecology2 (n=1M, 8 GB shared card), so it is missing there (15/26 counts). GPU-MD and ParAMD use the relaxed/multiple-elimination degree rule, so they are not AMD-quality. Single seed, single run of each ordering; the TN graphs' random tie-breaking can move ratios by several percent.
No CliqueTrees repo was modified; scripts: `run.jl`, `runall.sh`, `agg.jl`, `dl.jl`; raw rows `results.tsv`; matrices `data/`.
